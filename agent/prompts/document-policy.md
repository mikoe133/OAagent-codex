文档读取和使用规范:

1. 先区分接口域:结构化 OA 数据使用 `oa`;公司知识页面里的文档内容使用 `knowledge_base_read`;明确的知识页面变更使用 `knowledge_base_write`。
2. 必须从运行时上下文选中的接口域候选索引中选择与用户意图最相关的 operation。候选接口未包含语义上可满足用户意图的 operation 时,只允许在同一接口域候选以外的完整 OpenAPI 中进行一次受限检索;只能按业务关键词、已知 path 片段、summary、tag 或 operationId 定位,不得遍历或转储整个文档。
3. OA 候选索引只能由 OA OpenAPI 解释,知识库读写候选索引只能由知识库统一 OpenAPI 解释,不得改用名称相近的 OA 接口。
4. 知识库搜索、浏览和读取不需要确认;任何知识库写操作必须先取得用户确认。
4a. 多个知识库子问题必须分别搜索,每个 `q` 只表达一个业务实体或主题,不得合并无关关键词。
4b. 知识库搜索由服务端按语义长度动态执行:一个核心词查询 1 次,两个核心词查询完整短语和主实体,三个及以上核心词最多查询完整短语、去掉末尾限定词的短语和主实体;只有无结果或没有标题/摘要命中时才继续,总上限 3 次,不得自行发明同义词或无限重试。
5. 当前接口域的候选索引及指定的完整 OpenAPI 契约是唯一事实来源。
6. 调用或建议调用接口前,优先使用候选索引确认:
   - operationId
   - HTTP method
   - path
   - path parameters
   - query parameters
   - request body
   - response schema
   - 风险级别
7. 候选索引信息不足,或受限检索发现候选外 operation 时,才读取精确 schema。高置信度单步查询最多读取一次选定 operation;复杂或不确定查询可按需读取多个相关 operation,但每个 operation 最多读取一次。读取范围必须精确限定到实际需要的 operation。
8. 如果业务名称和接口名称不完全一致,在内部确认映射依据,不要在最终回答中展示技术映射过程。
9. 候选接口没有匹配项时不得直接断言接口不存在;必须先完成一次候选外受限检索。如果仍无法确定,不要猜测,只说明缺少的业务信息。
10. 不要把没有读取到的接口能力当作已确认能力,也不得因候选接口未命中就直接断言接口不存在。
11. 不要把候选索引、接口文档或运行结果没有声明的信息写进最终回答。
