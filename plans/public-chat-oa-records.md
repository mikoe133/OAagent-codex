# OA ID 统一后的四项改造

## 最终边界

- 公网唯一会话编号是 OA recordId；每条消息只有 requestId，不增加 runId。
- Agent 内部模型 threadId 和旧 agentSessionId 只用于上下文，不作为对外索引。
- OA Copilot 保存会话历史，Agent 的持久运行记录保存执行状态/结果/幂等摘要。

## 四项落实

1. Nginx 只将公开 /v1/models 和 /v1/sessions 子树路由到 Agent 3011；Web 3010 保留页面与同源适配，内部路由默认拒绝。
2. 消息必须有请求编号。用户+OA 数据源+recordId+requestId 唯一；同号同参数重放，同号不同参数冲突。容量拒绝不留下占位，已受理的未知结果不重跑。
3. 提供会话/历史/请求查询、显式取消及历史补存。断线继续执行，结果先本地落盘再写 OA；补存只追加缺少的消息，不调用模型。Web 不再整体覆盖历史。
4. 统一调度，控制全局/用户并发、队列、每分钟提交和等待/执行超时；同一会话串行，跨用户轮换。实际退出才释放执行名额。

## 部署与迁移

- Web 与 Agent 同版本上线，先排空旧任务，保留原 session 存储和持久卷。
- 现有 OA recordId 保持；有归属匹配的本地旧会话则复用上下文。旧浏览器打开列表即可切换到 OA ID。
- 旧 sessionId 幂等记录不自动推测映射；结果不明的旧请求必须核对后再迁移。
- 当前单进程使用独占文件创建及原子结果落盘，继续使用已有持久卷，不引入第二套聊天历史数据库。多副本调度需要后续共享事务存储/协调器。
- OA PATCH 整体覆盖协议没有 CAS。本项目统一写入者，但与外部 OA 写入者的并发需由 OA 协议升级解决。
- 未连接生产 OA/模型进行写入验证；部署前需要在联调环境确认 Copilot 响应 user_id、record、id、PATCH 行为与契约一致。
