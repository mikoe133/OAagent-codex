# 聊天图片与文件附件

聊天框回形针按钮支持每条消息最多 5 个附件：JPG、PNG、GIF、WebP 图片各 10 MiB；PDF、DOCX、TXT、MD、CSV、JSON、LOG、Office 文件与 ZIP 各 50 MiB。SVG、可执行文件及未列出的类型不接受。图片和 PDF 校验文件签名，不信任浏览器 MIME。下载需登录并通过 OA 会话归属检查；附件 ID 不能跨用户或会话使用。

## 模型能力（2026-09-29 核实）

来源：https://openrouter.ai/api/v1/models 。原始摘要见 `artifacts/chat-attachments/model-capabilities.json`。

| 当前 OpenRouter 模型 | 原生图片输入 | 文档文字分析 |
|---|---|---|
| GLM-5.3 | 不支持 | 支持提取后的文字 |
| Kimi K3 | 支持，实测通过 | 支持提取后的文字 |
| Qwen 3.8 Max | 支持，实测通过 | 支持提取后的文字 |
| DeepSeek V4 Pro | 不支持 | 支持提取后的文字 |
| DeepSeek V4 Flash | 不支持 | 支持提取后的文字 |

这五个模型的目录均没有声明通用 file 输入。文档由服务器提取文字，不是将 PDF/DOCX 原文件作为模型原生输入。Kimi 和 Qwen 分别通过 Responses API 及 OAagent 使用的 Codex SDK/模型中继识别纯红测试图片；结果见 `sdk-vision-probe.json`。测试只验证基本图片传递，不代表复杂图表、OCR 准确率或速度排名。Nexttoken 的图片能力未在本次验证范围内，界面不将其标记为可用图片模型。

## 自动判断与模型切换

附件卡片仅显示文件名、大小及移除按钮，不显示用途提示、用途切换、目标输入框或单次模型按钮。用户直接在消息中说明需求，由现有语义路由模型结合消息、近期对话、附件元数据及当前模型能力判断用途。前后端均不再使用关键词或正则推断附件意图。

- 路由复用现有 GLM/DeepSeek 并发竞速请求，一起输出接口域及附件决策，不额外增加串行模型调用。决策包含 `intent`（analyze/upload/both/clarify/ignore）、`requiresVision`、`visionModel`、中文判断原因；代码仅校验结构、模型能力及执行权限。
- 图片解析：路由模型判定确实需要查看图片且当前模型不支持图片时，本次切换为路由建议的 Kimi K3 或 Qwen 3.8 Max；默认建议 Kimi，用户指定 Qwen 时建议 Qwen。当前已选 Kimi/Qwen 时保留选择，不修改默认模型或模型选择器。
- TXT、PDF、DOCX 等可提取文字的文档：服务器提供正文，继续使用当前模型，不因文档解析而切换视觉模型。
- 自动切换时在实时 trace 显示“切换为 Kimi K3/Qwen 3.8 Max 模型用作文件解析（仅本次请求）”；历史、刷新及请求重放均保留该记录。原本选择 Kimi/Qwen 时不生成切换记录。
- 仅上传知识库：使用当前模型，不触发解析切换。目标页面在消息中指定；缺失或不唯一时先询问。
- Trace 先记录“附件用途判断”及模型给出的原因，再记录必要的模型切换。纯附件问答不默认进入 OA 接口查询。
- 用途不明确或仅选择附件时先澄清，不默认写入知识库；路由失败、无效输出或非法视觉决策同样转为澄清，不切换、不提取、不写入，也不猜测附件路径。
- 不支持解析的格式仍可发送，由回复说明格式限制；支持范围见下文。
- 发送准备失败时保留草稿。请求幂等与历史重试记录保留原始模型选择，自动切换只影响本次执行。

新界面不发送手动用途或目标字段，后端默认 `auto`。接口继续兼容历史 `attachmentMode: auto | analyze | upload` 和 `attachmentTarget`（最多 300 字）；这些字段参与幂等校验，并作为路由上下文；当前消息中的否定指令优先。

## 指令与行为

- “分析这些附件”或“这个人是谁”加人物介绍文件：解析并回答，不调用知识库写接口。
- “把这些附件上传到知识库页面 X”：保留原文件上传；先确定唯一目标页面并读取能力/限制，不需要解析文件。
- “总结附件，并上传到知识库页面 X”：解析及上传。
- “不要上传，只分析”：服务端阻止该附件轮次的知识库写入。
- 未说明用途、只有附件或询问上传能力：澄清用途/目标，不默认发布。写授权由路由模型判断；结构无效、路由失败或缺少可用知识库写路由时关闭写入。
- 服务端把本会话最近一条带附件消息中的有效附件作为追问候选，由路由模型判断是否相关；例如“他有哪些经历”可复用原文，无需重新传输文件。无关消息返回 ignore，不读取附件，也不影响新的独立知识库操作。

上传成功代表文件成为知识库页面的附件。将图片或文件节点插入正文仍需按知识库内容草稿流程预览、确认、apply，不把“已上传附件”误报成“已更新正文”。真实知识库写入权限、文件限制以其 capabilities 和上传返回值为准。本次未向生产知识库发布测试文件。

## 解析范围与限制

- UTF-8 文本：TXT、MD、CSV、JSON、LOG。
- PDF：提取文字，最多前 100 页。扫描页、图表及嵌入图片不自动 OCR；无文字时提示转图片后重新解析。
- DOCX：提取正文文字；内嵌图片不自动解析。禁用外部文件访问，解压总量最多 64 MiB、最多 5000 个 ZIP 条目。
- 每文件最多提供 24000 字符，截断会显式标注。PDF/DOCX 在独立进程内执行，超时 15 秒，V8 JS 堆上限 256 MiB；这不是整个进程 RSS 的硬限制。
- XLS/XLSX、PPT/PPTX、旧 DOC、ZIP 支持上传到知识库，暂不解析；提示转换格式。加密或损坏文件明确返回解析失败。

## 服务与部署

- `POST /api/chat/attachments?recordId=...`：浏览器发送原始二进制，`X-File-Name` 为 URI 编码文件名。BFF 使用登录 cookie 向 Agent 代理请求，不接收客户端本地路径。
- `GET /api/chat/attachments?recordId=...&id=...`：认证下载，强制 attachment、nosniff、no-store。
- 对应 Agent 路由：`POST /v1/sessions/{recordId}/attachments`、`GET /v1/sessions/{recordId}/attachments/{id}`。
- 聊天接口只发送 `attachmentIds`；历史保存服务器生成的描述信息，不存浏览器 File 或大段 base64。
- 文件存放在 `${AGENT_SESSION_STORE}.public-requests.attachments`，沿用会话持久化卷。单用户最多 200 MiB、单会话 50 个附件、同时最多 4 个上传。下载有效期 7 天，过期文件在该用户下一次上传时清理；删除会话会清理其附件。
- 知识库工具使用 `--attachmentId` 从当前消息授权附件解析二进制，以 `FormData` 发送 file/kind；不能通过 `--body` 或任意路径上传本地文件。相同会话/页面/附件采用稳定幂等键，工具重试不会重复创建附件。
- `deploy/nginx/oa-agent.rwkvos.com.conf` 为两个附件入口单独设置 `client_max_body_size 50m` 并关闭请求缓冲；普通消息仍是 128 KiB。部署时需更新 Agent/Web 镜像及这份 Nginx 配置；其他反向代理或入口网关也需允许该大小。
- 依赖 `pdfjs-dist`、`mammoth`、`jszip` 已记录于 agent/package.json 与根 lockfile，无需额外系统 OCR 工具。
