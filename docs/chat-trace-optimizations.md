# 对话完整性与速度优化

后续实现已升级为来源证据绑定的报告渲染，并已重载本地 Agent。当前行为和最新
验证见 [报告准确性与速度优化](grounded-report-optimization.md)；下文保留本阶段历史记录。

本次不增加意图关键词规则，不增加第二个模型审核。模型决定对象、数据源、字段、
关联方式和期间；服务端校验结构、权限、范围及返回结果，并在本地核对输出对象。

## 1. 对象与期间覆盖

只读工具新增 `report` 动作，由模型提交 `population` 清单查询与最多四个
`evidence` 证据查询。key、label、content 都引用查询的输出别名，可用于人员、
设备、项目等任意已授权实体，不固定员工类型、姓名或月份。

返回所有清单对象及其证据，分别标记 content、empty、not_found。不存在的记录
不能解释为没有进展，空正文不能解释为已经提交。分页游标、截断、重复标识和
同名对象会保留范围说明。

查询新增 `period`：单日期字段使用 `[start,end)`；区间记录使用相交条件，
endInclusive 区分包含结束日的周历与不包含端点的时间段。日期字段必须在元数据
中声明为日期类型。对于有期间要求的 report，模型声明 report.period，各个证据
查询必须使用同一期间。跨月正文没有按日证据时只说明相交周范围，不假装已拆分。

最终回答在本地检查对象名称覆盖；遗漏对象用已有来源的短摘录或空/缺记录说明
补充，最多展开 30 个，其余明确说明未展开。无需再调用模型。该检查只验证
“是否提到对象”，不验证自然语言结论是否正确，也不替代模型对用户范围的理解。
同名对象需要标识。未使用 report 的普通查询没有这项对象覆盖兜底。

## 2. 完成协议与等待

收到最终 `turn.completed` 且无活跃工具后，立即归还 SDK 迭代器，触发其子进程
清理；保留模型 usage、线程标识和错误处理。不能仅凭一段文字提前结束。
新增 answer_completion 指标，Trace 区分模型完成确认、连接释放、会话保存。

真实 SDK + 模拟子进程验证：子进程在完成事件后保持 10 秒，新的执行路径
约 233 ms 返回。该结果证明不会再等待进程退出尾部，不能作为线上固定节省
10 秒的保证；线上上游发送完成事件的时间仍需新 Trace 验证。

## 3. 减少模型往返

OA 路由的 runtime 直接提供本地已发布目录，按当前用户及管理员身份过滤，
不查 information_schema。已 describe 的定义按会话、用户、权限、版本和时效
复用；不同身份/版本不复用，验证失败的快照不提供缓存。缓存有会话数、实体数、
字节数和 10 分钟时效上限。

独立读取可以使用 `batch`，最多五条；report 也是一次工具请求。所有计划先
统一通过权限与字段校验，然后在同一个只读事务内顺序读取，减少模型往返，
不额外占用多条数据库连接。批次共享查询时间预算，并限制返回数据大小；
失败或分页不足仍须明确呈现。需要前一次结果才能规划的查询保留先后依赖。

## 4. 业务结果与 Trace

知识库、数据库命令遇到 `ok:false` 返回非零退出码，并保留错误 JSON。
Agent 和前端同时识别受控工具的顶层业务错误，修正旧 Trace 中退出码为零但
业务失败的状态。失败记录和后续成功调用各自保留，不覆盖历史失败。

OpenAPI 候选参数保留 enum/default，索引版本升级，避免旧缓存丢失约束。
任意工具文本或数据行内的 `ok:false` 不视为受控请求失败。
