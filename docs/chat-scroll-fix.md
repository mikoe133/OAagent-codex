# 回复期间滚动修复

旧消息列表在流式回复期间持续通过动画写入缓存的滚动位置，且跳过 scroll 事件
检测。内容收缩时缓存位置无法校正，手动滚动和按钮的原生平滑滚动也可能与该动画
冲突。完成回复后的正文尺寸变化没有独立监听；浮动按钮还在消息内容流内影响高度。

现在使用一个滚动控制器，读取实际视口位置，在内容或视口尺寸变化时合并为一次
动画帧更新。内容使用 border-box 尺寸观察，包含输入框预留 padding 的变化。
手动向上滚动暂停跟随，返回实际底部恢复跟随；按钮立即跳到最新位置。按钮移至
滚动容器外的独立浮层。会话切换按会话 ID 重建控制器，不依赖消息条数是否变化。

验证使用真实 MessageList/MessageBubble 组件和模拟 Trace、正文，在独立本机页面
完成，没有调用业务接口或回答模型：

- 追加 15 条 Trace 后底部距离为 0；PageUp 后暂停跟随，继续追加仍保持原阅读位置。
- 点击到底部、完成 80 段长回复后底部距离均为 0。
- 特大字体和缩小视口后底部距离为 0.5px（容许亚像素取整）。
- 增高输入框预留空间、切换相同消息条数的会话后底部距离均为 0。
- 六项滚动控制器回归覆盖增长、暂停/恢复、拖动滚动条、收缩后展开、尺寸变化和清理。
