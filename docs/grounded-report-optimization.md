# 报告准确性与速度优化

本轮针对最新进度概览 Trace 中的范围缩小、跨月遗漏、空正文编造成果和重复读取问题。
由现有路由模型理解用户期间，主模型选择来源重点，服务端依据元数据和实际证据校验、
渲染报告。没有增加模型审核请求，也没有按姓名、月份或任务关键词分支。

## 准确性

- 路由模型在原有请求中返回期间，重试不能丢失该期间。元数据声明日期字段及结束日
  是否包含，服务端据此生成区间相交条件和已注册的关联；模型不能另加时间筛选缩小期间。
- 未标注明确含义的字段默认仅允许用户明确指定时筛选。本例 `is_active` 没有已确认的
  业务含义，因此不能擅自用它排除人员。负向枚举筛选只保留已注册、未被排除的分类，
  不把未知分类解释为符合条件。
- 先读取对象清单，再在同一个只读事务内以实际对象标识限制证据查询。所有计划先通过
  权限、字段和范围校验，避免无效计划先读出部分结果。
- 每段来源摘录带对象绑定的证据标识和日期。主模型只返回选中的标识，服务端显示
  对应原文重点；跨对象标识不会被采用。自由改写或无效输出回退到已有来源摘录，
  不额外请求模型。报告成功后，未经证据核对的模型正文不会直接进入消息流。
- 所有对象都呈现实际状态。空正文不会生成具体成果；未找到记录只说明查询未找到，
  不推断未提交。分别说明对象清单完整性、证据行完整性和正文仅为摘录。

报告现在以模型选出的原文重点呈现进展，减少自由改写带来的事实偏差。跨月周报仍
按相交周展示：没有按日来源时，不能把整周内容精确拆为八月份内容。

## 速度

- 使用现有路由调用提取期间，不增加模型往返。服务端渲染与校验在本地完成。
- 返回给主模型的报告只包含对象状态和有预算的来源片段，按对象公平分配摘录，
  避免长正文挤掉后面的对象；内部保留证据，工具响应不重复发送全部记录。
- 等价的平铺查询、单数 join 和字段引用规范化，减少参数格式失败，未知参数仍严格拒绝。
- 当前对话轮次内，相同身份、元数据版本和完整报告计划可复用已读数据。降低正文
  预览长度不重新查库；不完整结果、分页结果、不同期间或身份不能复用。缓存有大小
  上限，轮次结束清理。这是当前读取轮次的复用，不是跨轮次实时数据缓存。
